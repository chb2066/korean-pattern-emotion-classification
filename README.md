# 전통문양 감성 분류 - 이미지 + 텍스트 융합 앙상블

문양 이미지 한 장과 사람이 쓴 설명 문장을 함께 받아, 22개 감성 라벨 중 **정확히
5개**를 고른다. 평가 지표는 F1@5 (모든 샘플의 정답이 5개이므로 precision =
recall = F1).

| | |
|---|---|
| 최종 성능 | **F1@5 = 0.8000** (val 446장) |
| 데이터 | 이미지 4,400장 · 라벨 22종 중 이미지당 5개 |
| 이미지 인코더 | DINOv3 ViT-L, **동결** |
| 텍스트 인코더 | 한국어·다국어 언어모델 5종, 전부 fine-tune |
| 융합 | 2토큰 self-attention |
| 앙상블 | 5개 모델 확률의 Dirichlet 랜덤서치 가중합 |
| 소속 | 한밭대학교 AiRLab (ETRI 과제) |

## 저장소에 무엇이 있고 무엇이 없는가

먼저 말해두는 게 낫겠다. **이 저장소는 그대로 돌려서 0.8000을 재현할 수 없다.**
데이터셋이 공개된 것이 아니기 때문이다.

들어 있는 것 - 학습·추론·분석 코드 전부, 설계 근거와 실험 기록, 모델 구성과
앙상블 가중치(`inference/config.json`).

빠진 것과 이유:

| 빠진 것 | 이유 |
|---|---|
| 모델 가중치 12개 (약 12GB) | GitHub 파일 한도 100MB 를 넘는다 |
| val 확률 캐시 `*.npz` | ETRI 이미지 ID 446개가 들어 있다 |
| 원본 이미지와 어노테이션 | ETRI 과제 데이터라 재배포하지 않는다 |
| 발표자료 | 과제 내부 문서 |

## 구성

**이미지 - DINOv3 (동결)**

CLIP, SigLIP2, FG-CLIP2, DINOv3 를 비교했을 때 이미지만으로 예측하는 성능이
가장 좋았다. 학습 중에 가중치를 건드리지 않고 "이미지를 벡터로 바꾸는 고정된
도구"로만 쓴다. 정말 얼리는 게 맞는지는 ConvNeXtV2 로 4조건을 따로 비교해서
확인했다.

**텍스트 - 언어모델 5종 (fine-tune)**

입력은 사람이 쓴 설명 문장 하나뿐이다. 문양유형·재질·시대 같은 구조적
메타데이터는 넣지 않는다.

| 모델 | 성격 | 단독 F1@5 |
|---|---|---:|
| `monologg/kobigbird-bert-base` | 희소 attention (BigBird) | **0.7861** |
| `klue/roberta-large` | 한국어 전용, 뉴스·위키 | 0.7794 |
| `xlm-roberta-large` | 100개 언어 다국어 | 0.7753 |
| `bert-base-multilingual-cased` | 104개 언어, xlmr 과 세대가 다름 | 0.7753 |
| `beomi/kcbert-large` | 커뮤니티·구어체, 도메인이 가장 멂 | 0.7682 |

**융합 - 2토큰 self-attention**

이미지 벡터와 텍스트 벡터를 같은 1024차원으로 맞추고, 둘을 "토큰 2개짜리
시퀀스"로 취급해 self-attention(Q=K=V)을 한 번 태운다. 이미지가 텍스트를,
텍스트가 이미지를 각각 한 번씩 참고한 셈이다. 그 출력을 이어붙여 22개 라벨
점수를 내고 상위 5개를 고른다.

## 실험에서 알게 된 것

### 1. 텍스트 인코더를 얼리면 안 된다 - 이게 가장 큰 차이였다

| 텍스트 인코더 처리 | F1@5 |
|---|---:|
| 동결 (head 만 학습) | ~0.68 |
| fine-tune (최종) | 0.78~0.79 |

이미지는 얼리는 게 맞고 텍스트는 얼리면 안 됐다. 두 인코더를 같은 방식으로
다룰 이유가 없다는 것이 이 프로젝트에서 가장 값비싼 교훈이다.

### 2. 학습률에서 실제로 중요한 건 backbone 하나뿐이었다

새로 만든 융합 레이어는 크게(1e-3), 이미 잘 학습된 언어모델은 조금씩(1e-5 ~
1.5e-5) 움직이게 했다. 그런데 "head 도 꼭 빠르게 배워야 하나"를 직접 확인해
보니 head 는 낮은 학습률로도 잘 수렴했다. **backbone 학습률을 낮게 유지하는
것 하나만 중요했고**, 이걸 올리면 0.78 → 0.58 로 무너진다.

### 3. 무거운 attention 이 오히려 손해였다

이미지의 패치 토큰 256개까지 attention 에 태우는 구조를 먼저 시도했는데 성능이
떨어졌다. 데이터가 4,400장뿐이라 무거운 구조를 학습시킬 여력이 없다. 그래서
토큰 2개짜리로 최대한 가볍게 만들어 그 문제를 피했다.

### 4. 앙상블 이득은 "다른 예측"이 아니라 "경계에서의 미세한 확신 차이"에서 나온다

텍스트 소스는 하나로 고정하고 **아키텍처만 다르게** 해서 다양성을 확보했다.
5개 모델의 top-5 예측 자카드 유사도는 0.74~0.79 로 꽤 높다. 그런데도

- 단순 평균: 0.7946
- Dirichlet 랜덤서치 가중합: **0.8000**

처음에는 klue-bert 를 넣은 4개 조합으로 0.7991 까지 갔다가 0.8 에 못 미쳤다.
mbert 와 kobigbird 를 추가하고 2~6개 전체 조합을 다 훑은 끝에, klue-bert 대신
kobigbird 를 쓴 5개 조합이 정확히 0.8000 으로 가장 좋았다.

### 5. 남은 오차는 모델이 아니라 라벨 정의에 있다

val 446장을 뜯어보면 **5개 중 0개를 맞힌 샘플이 한 장도 없고**, 4개 이상 맞힌
비율이 77.1% 다. 대신 라벨별 편차가 크다.

| | 라벨 | F1 |
|---|---|---:|
| 잘 맞힘 | 풍성한 / 단순한 | 0.909 / 0.893 |
| 못 맞힘 | 신비한 / 고급스러운 | 0.656 / 0.660 |

정답 개수 문제가 아니다. 우아한(GT 126장)도 낮고, 익살스러운(GT 9장)은 오히려
0.824 다. **개념이 추상적인 라벨일수록 저조하다.** 그리고 모델이 확신이 없을 때는
고빈도 라벨(조화로운 GT 291, 고전적인 GT 273)로 쏠려서 의미가 가까운 세밀한
라벨의 자리를 빼앗는다.

그래서 다음 레버리지는 모델이 아니라 **애매한 라벨의 정의와 어노테이션
가이드라인**에 있다고 본다.

### 채택하지 않은 것

- `koelectra-base` - 단독 0.745 로 낮음
- `mdeberta-v3-base` - 학습 중 loss 가 NaN 으로 발산
- `deberta-v3-xlarge-korean` - `tokenizers` 호환성 문제로 로딩 실패
- 메타데이터 병용 - 성능 차이가 ±0.003~0.005 로 잡음 수준이었고, 설명 문장만
  쓰는 것이 원래 설계 의도였다

## 실행

데이터셋이 있어야 학습과 앙상블이 돌아간다.

```bash
export PATTERN_DATA_ROOT=/path/to/orig_4.4k_260519

pip install -r inference/requirements.txt

python train/train_fusion_final.py --desc_only    # 모델 1개 학습
python train/ensemble.py                          # 5개 가중치 탐색
python val/analyze_val.py                         # val 결과 분석
```

추론은 데이터셋 없이 가중치만 있으면 된다.

```bash
cd inference
python infer.py --image <이미지경로> --description "<설명 문장>"
```

DINOv3 이미지 특징은 미리 뽑아 두는 구조라 학습 중에 이미지 픽셀을 다시 읽지
않는다. 다만 `dataset.py` 의 `load_records()` 가 split 을 만들 때 이미지 파일의
존재 여부를 확인하므로, 동일한 3,954 / 446 split 을 재현하려면 원본 파일 자체는
있어야 한다.

## 재현성

시드 42 로 고정했다. 데이터 셔플, 모델 초기화, dropout 등 무작위성이 들어가는
지점에 전부 적용했고, 같은 데이터가 있으면 `ensemble.py` 재실행 시 0.8000 이
그대로 나오는 것을 확인했다.
