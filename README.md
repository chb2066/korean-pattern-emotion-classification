# 전통문양 감성 분류 - 이미지 + 텍스트 융합 앙상블

흑백 문양 이미지 한 장과 이미지에 대한 설명 문장을 함께 받아
사람이 만든 22개의 감성 라벨 중 5개를 고른다. 
평가 지표는 F1@5 (모든 샘플의 정답이 5개이므로 precision =recall = F1).

| | |
|---|---|
| 최종 성능 | **F1@5 = 0.8000** (val 446장) |
| 데이터 | 이미지 4,400장 · 라벨 22종 중 이미지당 5개 |
| 이미지 인코더 | DINOv3 ViT-L, **동결** |
| 텍스트 인코더 | 한국어·다국어 언어모델 5종, 전부 fine-tune |
| 융합 | 2토큰 self-attention |
| 앙상블 | 5개 모델 확률의 Dirichlet 랜덤서치 가중합 |

## 재현 가능 여부

데이터셋은 공개할 수 없어 표기 성능은 재현할 수 없으나, 
문화포털 등의 사이트에 있는 전통문양 데이터들에 적용해 볼 수 있다. 


## 문제 해결을 위한 데이터 특징
데이터 내 3가지 주요 특징이 있다.
1. 데이터 수가 적다.
2. 이미지 데이터가 흑백 선화 데이터이며, 시각적으로 유사하지만 라벨이 다른 데이터가 많다.
3. 텍스트 내에 형용사 키워드의 의미가 내포된 경우가 많고, 글의 서술량이 길다.

## 핵심 접근
데이터의 가장 큰 특징은 이미지와 텍스트 내 추출 가능한 특성량의 상한이 다르다.
적은 데이터를 다루면서도 텍스트의 특징을 최대로 활용하면서, 이미지 특징을 동시에 
반영할 방법을 찾는 것이 핵심이다.

## 구성

**이미지 - DINOv3 (동결)**

이미지만으로 성능을 측정하는 경우 ConvNeXtV2, SigLIP2, FG-CLIP2, DINOv3 중
Dinov3가 가장 좋았다. 학습 중에 가중치를 건드리지 않고 
이미지의 feature를 뽑는 역할로만 사용했다. 

**텍스트 - 언어모델 5종 (fine-tune)**

입력은 이미지에 대한 설명 문장 하나뿐이다. 문양유형·재질·시대 같은 구조적
메타데이터는 넣지 않는다.

| 모델 | 성격 | 단독 F1@5 |
|---|---|---:|
| `monologg/kobigbird-bert-base` | 희소 attention (BigBird) | **0.7861** |
| `klue/roberta-large` | 한국어 전용, 뉴스·위키 | 0.7794 |
| `xlm-roberta-large` | 100개 언어 다국어 | 0.7753 |
| `bert-base-multilingual-cased` | 104개 언어, xlmr 과 세대가 다름 | 0.7753 |
| `beomi/kcbert-large` | 커뮤니티·구어체, 도메인이 가장 멂 | 0.7682 |

**융합 - 2토큰 self-attention**

이미지 벡터와 텍스트 벡터를 같은 1024차원으로 맞추고, 둘을 "토큰 2개짜리
시퀀스"로 취급해 self-attention(Q=K=V)을 한 번 적용한다. 이미지가 텍스트를,
텍스트가 이미지에 대한 영향을 상호적으로 받을 수 있게 했다. 
이렇게 만든 출력을 사용해, 22개 라벨 점수를 내고 상위 5개를 고른다.

## 실험에서 알게 된 것

### 1. 텍스트 인코더를 fine-tuning 해야한다.

| 텍스트 인코더 처리 | F1@5 |
|---|---:|
| frozen (head 만 학습) | ~0.68 |
| fine-tune (최종) | 0.78~0.79 |

데이터 특성에서 보인 것과 같이 상대적으로 데이터 량이 작기 때문에
인코더를 얼리는 것보다 fine-tuning 할 때, 더 높은 성능을 보였다.


### 2. 무거운 attention 은 오히려 손해였다

이미지의 패치 토큰 256개까지 attention 에 태우는 구조를 먼저 시도했는데 성능이
떨어졌다. 데이터가 4,400장뿐이라 무거운 구조가 악영향을 끼친 것으로 유추한다.
그래서 토큰 2개짜리로 최대한 가볍게 만들어 그 문제를 해결했다.

### 3. 남은 오차는 모델이 아니라 라벨 정의에 있다

val 446장을 뜯어보면 5개 중 0개를 맞힌 샘플이 한 장도 없고, 
4개 이상 맞힌 비율이 77.1% 다. 대신 라벨별 편차가 크다.

| | 라벨 | F1 |
|---|---|---:|
| 잘 맞힘 | 풍성한 / 단순한 | 0.909 / 0.893 |
| 못 맞힘 | 신비한 / 고급스러운 | 0.656 / 0.660 |

라벨 불균형이 주는 영향이 생각보다 적다. 
train 데이터 내 라벨 수가 적어도
실제 validation 시에는 높은 성능을 보이는 경우도 있었고(EX: 익살스러운),
tarin 데이터 내 라벨 수가 적지 않아도
실제 validation 시에는 낮은 성능을 보이는 경우도 있었다(우아한).

실제 라벨 유추에 큰 영향을 준 요소는 개념이 얼마나 추상적인가와 같은 요소이며
추상적 요소가 과내포된 라벨의 경우 상대적으로 의미가 유사한 라벨로 예측되거나
빈도수가 매우 높은 라벨들로 예측되는 경우가 발견되었다.

따라서, 추가 성능 향상을 위해서는 라벨에 대한 추가 정의 등이 필요한 것으로 예상된다.

## 저장소 구조

```
train/
  train_fusion_final.py   학습 (--desc_only 로 설명 문장만 사용)
  dataset.py              레코드 로딩, split, 감성 단어 redaction, top5 F1
  ensemble.py             5개 모델 가중치 탐색
  METHOD.md               설계 근거와 실험 경과
  RESULT.md               실험 결과 기록
inference/
  infer.py                배포용 추론
  config.json             모델 구성과 앙상블 가중치
  docs/MODEL.md           모델 구조 설명
  docs/fusion_architecture.html   구조도
val/
  analyze_val.py          라벨별 성능, 혼동 분석, 모델 간 예측 다양성
  README.md               분석 결과 요약
gradio/
  app_gradio.py           데모
  collect_description.py  설명 문장 수집 도구
```

## 실행

데이터셋이 있어야 학습과 앙상블이 돌아간다.

```bash
export PATTERN_DATA_ROOT=/path/to/orig_4.4k_260519

pip install -r inference/requirements.txt

python train/train_fusion_final.py --desc_only    # 모델 1개 학습
python train/ensemble.py                          # 5개 가중치 탐색
python val/analyze_val.py                         # val 결과 분석
```

추론은 데이터셋 없이 가중치만 있으면 된다.

```bash
cd inference
python infer.py --image <이미지경로> --description "<설명 문장>"
```

DINOv3 이미지 특징은 미리 뽑아 두는 구조라 학습 중에 이미지 픽셀을 다시 읽지
않는다. 다만 `dataset.py` 의 `load_records()` 가 split 을 만들 때 이미지 파일의
존재 여부를 확인하므로, 동일한 3,954 / 446 split 을 재현하려면 원본 파일 자체는
있어야 한다.

## 재현성

시드 42 로 고정했다. 데이터 셔플, 모델 초기화, dropout 등 무작위성이 들어가는
지점에 전부 적용했고, 같은 데이터가 있으면 `ensemble.py` 재실행 시 0.8000 이
그대로 나오는 것을 확인했다.
