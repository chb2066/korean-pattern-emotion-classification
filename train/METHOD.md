# 전통문양 감성 분류 — 이미지+텍스트 융합으로 F1@5 0.80 달성 (2026-08-11, 최종 갱신 2026-08-21)

## 1. 목표
이미지 4,400장, 각 이미지에 감성 라벨 정확히 5개(22종 중), 이 5개를 얼마나 잘 맞히는지가
평가 지표(F1@5, 사실상 top-5 정답률과 같음). **이미지와 텍스트(description) 둘 다 반드시
사용**해서 F1@5 0.8 이상을 목표로 함. 최종 **0.8000** 달성.

> **정정 2건**: (1) 처음에 "DB 캡션"이라는 텍스트 소스를 다양성 확보용으로 썼었는데
> (0.8117 나옴), 이 소스가 파일 맨 앞에 정답 라벨 5개를 그대로 적어놓은(leakage)
> 데이터라 **사용 금지** 판정을 받아 전면 폐기함. (2) 텍스트 입력에 description
> 말고 문양유형/재질/시대 같은 구조적 메타데이터도 같이 넣고 있었는데, **원래
> 의도는 description 텍스트만 쓰는 것**이었다는 게 확인돼서 전부 다시 학습시킴.

## 2. 전체 그림 (한 문장 요약)
"이미지를 잘 이해하는 모델(DINOv3)"과 "텍스트(description만)를 잘 이해하는 여러
언어모델"을 하나로 붙여서 각각 학습시킨 다음, 서로 다른 언어모델 5종을 가중평균해서
최종 답을 냈다.

## 3. 두 인코더

### 이미지 인코더 — DINOv3 (고정, 학습 안 시킴)
- Meta에서 만든 self-supervised 비전 모델(facebook/dinov3-vitl16-pretrain-lvd1689m).
- 이 프로젝트에서 여러 백본(CLIP, SigLIP2, FG-CLIP2, DINOv3)을 비교했을 때 DINOv3가
  이미지만으로 예측할 때 가장 성능이 좋았어서 선택.
- **가중치를 얼려서(freeze)** 썼음 — 이번 학습에서 DINOv3 자체는 전혀 안 바뀌고, 그냥
  "이미지를 벡터로 바꿔주는 고정된 도구"로만 사용. ConvNeXtV2로 "정말 얼리는 게
  맞나" 별도 재검증도 했는데(4조건 비교) 결론은 동일 — 프리즈가 맞음.

### 텍스트 인코더 — 5종 (전부 학습시킴, 진짜 fine-tuning, description만 입력)
| 모델 | 특징 |
|---|---|
| klue/roberta-large | 한국어 전용, 뉴스/위키 코퍼스 (하이퍼파라미터 튜닝됨) |
| xlm-roberta-large | 100개 언어를 같이 배운 다국어 모델 |
| beomi/kcbert-large | 커뮤니티/구어체 텍스트로 학습 - 도메인이 가장 다름 |
| bert-base-multilingual-cased | 104개 언어 다국어 모델(mBERT, xlmr과 세대가 다름) |
| monologg/kobigbird-bert-base | 희소attention(BigBird) 구조 - 단독 성능 최고(0.786) |

(시도했으나 폐기: koelectra-base — 성능 낮음(0.745) / mdeberta-v3-base — loss NaN 발산 /
klue-bert-base — 4개 조합엔 넣었지만 최종 5개(kobigbird로 교체) 대비 낮음 /
deberta-v3-xlarge-korean — 토크나이저 라이브러리 호환성 문제로 로딩 자체가 안 됨)

- 입력은 이미지에 대한 사람이 쓴 설명 문장(description) **그 자체만** — 메타데이터는
  안 넣음(위 정정 2번 참고).
- 이미지 인코더와 다르게 **이 모델들은 얼리지 않고 진짜로 학습(fine-tuning)시켰음.** 이게
  성능을 가장 크게 끌어올린 부분 — 대조군으로 얼린 채(frozen) 썼을 때와 비교하면 차이가
  뚜렷함:

| 텍스트 인코더 처리 | F1@5 |
|---|---|
| Frozen (가중치 고정, head만 학습) | ~0.68 |
| Fine-tune (전체 가중치 학습, 최종 배포) | 0.78~0.79 |

## 4. 이미지+텍스트를 어떻게 합쳤나 (융합, fusion)
1. 이미지 벡터 하나, 텍스트 벡터 하나를 각각 같은 크기(1024차원)로 변환.
2. 이 둘을 "토큰 2개짜리 아주 짧은 문장"처럼 취급해서, **self-attention**이라는 방식으로
   서로를 한 번 들여다보게 함 (Q=K=V가 이 2개 토큰 자체라서, 이미지가 텍스트를·텍스트가
   이미지를 각각 한 번씩 참고함).
3. 그 결과를 이어붙여서(concat) 최종 분류기(작은 신경망)에 넣어 22개 라벨 점수를 매기고,
   그중 확률 상위 5개를 최종 답으로 고름.
- 참고: attention을 아주 무겁게(이미지의 세부 조각 256개 단위까지) 쓰면 오히려 성능이
  떨어지는 걸 이 프로젝트에서 이미 확인했었음(데이터가 4천 장뿐이라 무거운 구조는 잘 못
  배움). 그래서 "토큰 2개짜리"로 아주 가볍게 만들어서 그 문제를 피함.

## 5. 학습 방식 디테일
- 데이터: 4,400장 중 3,954장 학습, 446장 검증(val) — 라벨 비율이 고르게 섞이도록 나눔.
- 텍스트 인코더와 새로 만든 융합 레이어의 학습 속도(learning rate)를 다르게 줌 — 이미 잘
  학습된 언어모델은 아주 조금씩만 건드리고(1e-5~1.5e-5), 처음 만든 새 레이어는 크게
  건드림(1e-3). "head도 꼭 빠르게 배워야 하나?" 직접 검증해봤는데, 사실 head는 낮은
  LR로도 잘 수렴함 — 진짜 중요한 건 "backbone LR을 낮게 유지하는 것" 하나뿐이었음
  (backbone LR을 높이면 0.78→0.58로 붕괴).
- 라벨 불균형 대응: AsymmetricLoss 사용. class-balanced sampler는 top-5 지표엔 오히려
  손해라서 안 씀.
- 모델별로 fine-tuning 설정(epoch, dropout 등)을 소폭 튜닝해서 검증 성능을 확인함.

## 6. 왜 모델을 5개나 만들었나 (앙상블)
텍스트 소스는 description 하나로 고정. 다양성은 **아키텍처를 다르게**(klue-roberta /
xlm-roberta / kcbert / mbert / kobigbird) 해서 확보 — 사전학습 코퍼스와 구조가 다르면
실수하는 패턴도 달라짐.

| 모델 이름 | 단독 성능(F1@5) |
|---|---|
| klue | 0.7794 |
| xlmr | 0.7753 |
| kcbert | 0.7682 |
| mbert | 0.7753 |
| kobigbird | 0.7861 |

5개 다 혼자서는 0.8을 못 넘었지만(0.77~0.79대), **서로 실수하는 지점이 다르다**는 게
핵심. 처음엔 klue_bert를 넣은 4개 조합으로 0.7991까지 왔는데 0.8에 살짝 못 미쳐서,
mbert·kobigbird라는 새 아키텍처를 추가하고 2~6개 전체 조합을 다 탐색한 끝에 klue_bert
대신 kobigbird를 쓴 5개 조합이 정확히 0.8000으로 가장 좋다는 걸 확인함.

- 5개를 단순 평균: 0.7946 (아직 부족)
- 각 모델에 가중치를 다르게 줘서 최적화: **0.8000** ← 최종 결과

## 7. 재현성
- **seed = 42로 고정**. 데이터 셔플, 모델 초기화, dropout 등 무작위성이 들어가는 모든
  지점에 시드를 적용해서, 같은 코드를 다시 돌리면 거의 동일한 결과가 나오도록 해뒀음.
  `ensemble.py`를 다시 돌려서 0.8000이 정확히 재현되는 것도 확인함.
- 코드: `train_fusion_final.py`(학습, `--desc_only` 플래그로 description-only 학습),
  `ensemble.py`(5개 모델 앙상블 및 최적 가중치 탐색).

## 8. 결과 한눈에
```
klue + xlmr + kcbert + mbert + kobigbird (전부 0.77~0.79대, description만 입력)
                    └──────────── 앙상블 ────────────┘
                        F1@5 = 0.8000  ✅ 목표(0.8) 달성
```

## 9. 실패한/채택 안 된 시도 (참고용)
- **koelectra-base**: 단독 성능이 낮음(0.745) → 제외.
- **mdeberta-v3-base**: 학습 도중 loss가 NaN으로 발산(0.165, 사실상 랜덤 수준) → 폐기.
- **deberta-v3-xlarge-korean**: 토크나이저 로딩 자체가 `tokenizers` 라이브러리 호환성
  문제로 실패(`Unigram` vocab 변환 에러) → 학습 시도조차 못 함.
- **klue-bert-base 포함 4/5개 조합**: 개별 성능은 나쁘지 않았지만(0.7780~0.7807), 앙상블
  조합 탐색 결과 kobigbird로 교체한 조합보다 항상 낮게 나와서 최종에서 제외.
- **메타데이터 포함 버전**: 원래 의도(description-only)와 달라서 전면 재학습. 다만
  메타데이터 유무에 따른 성능 차이 자체는 ±0.003~0.005로 크지 않았음(노이즈 수준).
